# Scheduled mocks

Admin flow: create a mock with a Bangladesh-time start, complete Listening (40 scored answers and audio), Reading (40 scored answers), and Writing (Task 1+2), then open `/admin/mocks/<id>`, select a published Speaking question set, and select **Open registration**. That action atomically freezes the paper, access tier and absolute timetable and publishes its public waiting room. Editing source modules afterward does not change a scheduled paper. Create a new mock for a different paper/time.

Candidate flow: verified login → register before the start → waiting room → join/resume. Premium registration requires an active subscription at registration. A booked registration remains valid if the subscription expires before the exam. Concurrent joins reuse one attempt. A late join receives the current stage, not a fresh timer. Full practice tests remain Listening/Reading only; scheduled mocks always contain Listening/Reading/Writing/Speaking for newly scheduled mocks. Existing frozen three-module papers are preserved.

All stages use absolute deadlines calculated from the scheduled start. An early Submit locks the stage until its deadline. Expired stages are settled on the server from the most recent autosave, including when the browser was closed. Late request bodies are never accepted as a replacement for expired answers. Autosaves are sent after a short typing pause, periodically while typing, and more frequently in the final seconds; offline answers also remain in sessionStorage. Candidates must reconnect before the deadline for unsaved device-only edits to count.

Listening/Reading are scored automatically. Writing is automatically assessed through a dedicated signed Vercel Queue job scheduled at Join for the fixed exam end, independent of the candidate browser. The worker settles abandoned attempts, evaluates saved Task 1+2 through the configured Writing provider, persists rubric feedback, and retries provider failures up to three times with a database lease. Mock evaluation is included in the registered event rather than consuming standalone product quotas. Admin can retry failed jobs or manually review exceptional papers in **Schedule & results**. Publication is blocked until the timetable has ended and every joined candidate's Writing has an AI grade or an admin review. Results and answer keys are withheld by the API until publication; published results are account-owned and retained rather than relying on the guest attempt's 24-hour expiry. Published Writing grades cannot be edited, including by a redelivered AI job. AI failures or unscorable answers block publication until reviewed. Blank submissions receive band 0 without a provider request. No-show registrations have no scored attempt.

Registration succeeds only after the reminder has been queued (a failed queue request can be retried safely). Registration schedules a transactional reminder approximately ten minutes before the start. The signed Vercel Queue callback uses a database lease and Resend idempotency key. Dates over the seven-day queue retention limit are handled by six-day delayed continuation messages. Delivery uses the existing Resend/SMTP configuration; no cron or new email key is required. No real reminder emails are sent by the integration test.

Apply `migrations/022_scheduled_mocks.sql` before deploying the routes. It extends the attempt kind constraint and adds mock events, registrations, locks, and an allowlisted OAuth return path. Existing practice answers and modules are not rewritten. Vercel must deploy the new queue trigger in `vercel.json`.

Tests: `node --test tests/scheduled-mocks.test.mjs tests/cambridge-seamless-flow.test.mjs tests/verification.test.mjs`. Database lifecycle test: `MOCK_TEST_DATABASE_URL=<isolated test branch URL> node scripts/test-scheduled-mocks.cjs`. This script creates synthetic records and changes their timestamps only in the supplied isolated database; never pass production credentials.

To reuse a paper: create a draft mock with its own title, then choose **Use existing test** on its card (or in Schedule & results). Search Cambridge, More Books or Practice, select a test and modules, then **Copy into mock**. Only selected modules are replaced; missing Writing can come from another source. Source labels are removed from copied document metadata and part titles, while passages, audio, images and answer keys are preserved. The source paper is not modified. Copying is blocked after registration opens.

Speaking follows Writing at its absolute scheduled boundary (default 15 minutes, configurable 5–60). The existing three-part Speaking room records and privately uploads each completed answer. Its timer uses the scheduled deadline, not room entry time. Uploads and voice requests are gated by ownership, the Speaking window and early-submission lock. Two independently leased queue jobs evaluate Writing and Speaking after the event ends, even when the browser is closed. Standalone Speaking API cannot evaluate a mock or reveal an unpublished mock score. Admin may retry or manually review either module; publication requires both. Local audio that was never uploaded cannot be evaluated after the browser closes.
